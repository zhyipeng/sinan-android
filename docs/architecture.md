# 技术架构

## 技术基线与当前实现

Kotlin + Android 原生 View，最低 API 26，编译与目标 API 36。当前工程实际只有 `app` 与 `core/search` 两个模块，不提前拆分大量 Gradle 模块。

截至 2026-11-13，`app` 已实现应用网格、九宫格、按需面板和磁贴；`core/search` 已有 `PinyinProvider` / `TinyPinyinProvider`、`T9SearchEngine` 和 JVM 测试。`AppGridView` 管理查询与结果代次，`AppRepository` 后台构建快照。工具内小时汇总和习惯排序已接入，系统事件与可选增强仍未实现。

| 组件 | 职责与依赖边界 |
| --- | --- |
| AppRepository | 获取可启动入口、用户配置文件标识及应用变化；输出平台无关条目 |
| PinyinProvider / IndexBuilder | 离线词组拼音、变体、别名与 T9 编码；后台构建快照 |
| SearchEngine / UsageRanker | 纯 Kotlin 匹配与确定性排序；接收索引、时钟、统计快照 |
| UsageRepository | 工具内事件、可选系统事件、聚合与清除 |
| SearchController | 管理查询、面板会话及过期搜索任务取消 |
| FloatingPanelManager | WindowManager、焦点、触摸边界、显示/隐藏及资源释放 |
| AppLauncher | 根据 profile + component 启动，处理失效入口与受限资料 |
| EntryPoints | Activity、快捷方式、磁贴及可选悬浮球，共用唤出流程 |

目前不引入 DataStore 或 Room；本地小时汇总使用 AtomicFile，后续复杂设置/系统事件若引入其他存储需另行评估。拼音已采用 TinyPinyin 2.0.3 并由接口隔离，词组与许可范围见 [依赖说明](dependencies.md)。

## 数据流

```text
应用扫描/变更 → 词组拼音与数字编码 → 不可变索引快照
系统可选事件 + 工具内启动 → 去重与聚合 → 使用特征快照

用户主动唤出 → 固定索引/使用快照 → 默认推荐
T9 输入 → 匹配候选 → 等级排序 → 按 AppId 去重 → 网格
点击 AppId → 系统启动请求 → 记录提交结果 → 收起面板
```

应用启动请求被系统接受不等于目标已展示在前台。无可靠确认时，事件应标为工具内“启动请求”，不可宣称为实际系统使用事件。

## 窗口与生命周期

面板状态建议为 `Hidden → Opening → Visible → Launching/Closing → Hidden`。同一时刻只允许一个面板实例；重复唤出按状态合并，所有 WindowManager 变更在主线程串行执行。

- 打开时检查权限与宿主状态；无悬浮权限进入 Activity 降级视图。
- 跨应用窗口拟使用 `TYPE_APPLICATION_OVERLAY`；键盘由应用自身绘制，焦点、返回键、触摸穿透与外部点击需专门验证。
- 普通面板按需创建，关闭后移除窗口、解除监听和释放宿主；不默认依赖永久常驻服务。
- 可选悬浮球需要单独验证合法的服务生命周期、通知、进程终止恢复与用户关闭路径。
- 后台刷新只供下次面板使用；应用卸载等失效可令当前格子失效，不在手指按下时重新排位。
- 搜索任务具有递增查询版本号，只发布当前查询与索引版本对应的结果。

## 标识、索引与数据

应用 ID = 用户资料序列号 + 包名 + 完整 Activity 名。序列号由 Android 适配层取得；不使用对象哈希，也不假设包名能唯一表示启动入口。

普通应用能看到的应用和资料范围受平台约束；工作资料支持属于兼容性验证项，不承诺跨全部资料访问。系统使用事件常只有包或 Activity 线索，无法可靠定位到入口时按资料/包级保存统计并明确共享，不能伪造入口级精度。

索引仅保存文本与匹配元数据，不包含图标 Bitmap。图标单独按密度与资料身份缓存，采用有界内存缓存。扫描与索引在后台完成，通过原子替换快照发布；增删包、语言变化、名称变化后更新。进程冷启动没有缓存时显示加载状态，不在主线程同步全量扫描。

## 需要设备验证的系统边界

原会话提及的 Android API 行为只作为待验证线索。实现时应查阅对应目标版本的最新官方文档，完成下列验证后才能确认入口方案。

| 验证项 | 通过标准 |
| --- | --- |
| Activity / 磁贴主动唤出 | 锁屏与解锁状态行为清晰，允许路径稳定可用 |
| 后台 Activity 与服务启动限制 | 不依赖隐藏悬浮窗权限绕过限制；合法路径实机可重复 |
| 悬浮球服务 | 验证服务类型、后台启动条件、通知和关闭清理 |
| 悬浮窗与底层触摸 | 不吞掉面板外交互，不制造误触或卡住返回键 |
| 应用可见性 | 最小声明能列出预期启动入口；工作资料不可见时降级 |
| UsageStats 事件 | 授权撤销、有限事件窗口、重复事件、时钟改变有处理 |
| 屏幕适配 | 全面屏手势、导航栏、横屏、折叠屏、字体缩放可操作 |

建议覆盖最低支持版本、API 35/36 和至少两类常见厂商真机。仅有编译和 Lint 通过不能关闭这些任务。

## M1 已实现的系统适配

- `MainActivity`：未授权时展示普通应用网格和权限入口；有权限且从桌面/磁贴打开时转入面板。「设置」通过内部标记强制打开普通页面。
- `PanelActivity`：透明的前台 Activity，使用原生 Dialog 的窗口管理和返回/外部点击分发，窗口类型明确设置为 `TYPE_APPLICATION_OVERLAY`。每次唤出仅保留一个实例，关闭或宿主停止时移除窗口；配置重建时不额外结束新宿主。
- 该宿主是用户主动唤出的前台界面，不让隐藏进程直接启动悬浮服务。默认未启用球时没有常驻服务或前台通知；0.5 可选球服务见下节，不包含后台保活或开机启动。
- 磁贴由系统绑定 `TileService`，受 `BIND_QUICK_SETTINGS_TILE` 保护。API 34+ 使用 PendingIntent 重载收起通知栏并启动；API 26–33 才使用旧 Intent 重载。锁定状态通过 `unlockAndRun`，锁屏流程尚未专项验收。
- `AppRepository` 仅访问 `Process.myUserHandle()`，从 `LauncherApps` 获取入口，再与最小 MAIN/LAUNCHER 查询相交，排除合成的应用详情页；不申请全量包查询或使用情况访问权限。
- 文本扫描和图标加载使用两条后台工作线程；文本列表保留会话快照，图标 ConstantState 使用 48 项 LRU。包变化使下次打开时的快照失效，不在手指准备点击时重排当前网格。
- 图标回调以绑定 ID 和视图代次防止异步错位，缓存同步命中允许在视图挂载前赋图。初始版本无输入按系统名称排序；0.4 起按本地工具请求排序（见下节），不记录查询数据。
- 系统配置改变时清空文本和图标缓存；图标任务以索引代次检查，避免失效前的异步图标重新填入新缓存。
- 界面采用图标品牌蓝 `#2954CE`、浅底 `#F5F7FC`、深底 `#151D30`、正文 `#192743` / `#EAF0FF`，原生字体。网格随实际可用宽度适配 2–6 列；普通手机竖屏通常为四列。

接口依据：[LauncherApps](https://developer.android.com/reference/android/content/pm/LauncherApps)、[WindowManager.LayoutParams](https://developer.android.com/reference/android/view/WindowManager.LayoutParams)、[TileService](https://developer.android.com/reference/android/service/quicksettings/TileService)。实际兼容结论以 [设备验证记录](validation-m1.md) 为限。

## T9 接入（0.3.0）

- `AppCatalog` 缓存启动入口、按 AppId 的映射和只读 T9 索引；`AppSnapshot` 在每次打开时附加固定的使用分数。全部拼音转换与编码在后台扫描阶段完成，不在按键或图标绑定时重新转换。
- 搜索独用一个后台执行器，与图标加载分开。查询最长 32 位，每次变化递增版本并取消旧任务，发布前同时核对视图代次和查询版本；新结果到达前暂时禁用网格点击。
- 触摸按下时捕获 AppId 对应的条目和查询版本，避免旧触摸落在新结果的位置；启动处理中不发布新的结果。
- 输入只使用 TextView 和应用内按键，不引入 EditText / 系统 IME。空查询恢复会话推荐顺序，非空查询按等级、同级使用分数、具体程度及稳定 ID 排序。
- `AppGridView` 在测量前决定上下或左右布局，重用 LayoutParams；横屏时结果区位于左侧、键盘位于右侧。按键行高由实际字体度量确定，覆盖 1.5 倍字体的两行数字/字母。
- 面板最大宽 560dp，竖向显示区域使用 78% 高度，横向使用 90%。API 30+ 从应用上下文的 WindowMetrics 读取最大显示边界，旧版本使用显示器实际尺寸；可见期间注册 DisplayListener，关闭时解绑，防止兼容模式下旋转后继续沿用竖屏尺寸。
- T9 版本未实现使用历史；0.4 接入如下本地统计。查询日志、别名编辑、置顶仍未实现，不增加网络或使用情况访问权限。

## 本地排序接入（0.4.0）

- `UsageHistory`、`UsageRanker`、`UsageCodec` 位于纯 JVM 模块；时钟/时区显式传入，固定数据覆盖滚动保留、衰减、损坏格式和排序等级隔离。
- `LocalUsageRepository` 独立单线程执行所有加载、汇总、清理、评分及原子写入。路径为应用私有 `no_backup/usage-summary.bin`，不进入自动备份。
- `AppRepository.launch` 在系统调用正常返回后排队一次记录；失败返回不计数。统计异常不阻断启动或搜索。
- 文本目录与统计分离缓存，每次打开读取当下的分数副本。T9 索引复用，当前网格内分数固定；清空成功后显式刷新普通页面。
- 普通页面顶部「使用记录」展示采集/保留说明与清空按钮；面板通过键盘左下角设置图标访问。
- 文件有版本、容量界限与 CRC 校验。未知格式/损坏不被新统计覆盖，降级名称排序并提示清空恢复。CRC 仅用于损坏检测，不是加密。

具体字段、评分和边界见 [本地智能排序](usage-ranking.md)。

## 面板简化

悬浮窗移除标题行和顶部设置/关闭按钮。`AppGridView` 仅在加载、失败或无结果时显示状态，不再显示应用/匹配数量或输入提示。数字栏与九宫格组成独立列：竖屏位于网格下方，横屏位于网格右侧，数字始终显示在按键上方。图标按钮提供 contentDescription，退格长按清空，设置图标通过宿主回调路由。

## 可选悬浮球（0.5.0）

- `FloatingBallController`（Application 持有）协调开关及面板宿主集合，服务观察状态以显隐球；只从前台设置明确开启，开启状态不跨进程保存。
- `FloatingBallService` 管理一个 48dp 非聚焦 Overlay、specialUse 前台通知及关闭动作。屏幕/锁定、通知禁用、显示和悬浮权限变化触发协调，关闭注销监听并释放窗口。
- `BallPositionStore` 只在后台串行读写贴边方向与高度比例，应用备份仍关闭；默认右侧中部，旋转按安全边界重新定位。
- 面板仍由原 `PanelActivity` 承载，成功显示后登记宿主，停止/销毁时移除自己的登记，避免球与面板同时展示。

系统依据和边界见 [悬浮球](floating-ball.md)，实测见 [专项验证](validation-ball.md)。
