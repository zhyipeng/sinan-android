# T9 匹配与智能排序

状态：2026-11-13 已实现纯 Kotlin T9 引擎、固定样例测试和 Android 九宫格接入。智能排序、行为记录及使用习惯参数仍为设计提案。验证与边界见 [T9 验证记录](validation-t9.md)。

## 索引和规范化

每个可启动入口生成：名称、词组拼音音节变体、简拼、全拼、英文名称和别名的数字编码。拼音转换仅在建索引时运行，按键后线性扫描不可变内存快照，不预建所有简拼/全拼混合组合。

字母映射：`abc→2 def→3 ghi→4 jkl→5 mno→6 pqrs→7 tuv→8 wxyz→9`。英文使用 `Locale.ROOT` 小写；音调去除，`ü/u:/v` 统一为 `v`；分隔符作为边界处理，避免把不相关片段拼接成虚假命中。多音字优先词组词典，仅生成经过词典确认的有限变体，不笛卡尔积穷举所有读音。

用户于 2026-11-13 确认：查询支持 ASCII `0–9`，0/1 按字面匹配数字名称，2–9 同时表示字母 T9 编码和原始数字。底行使用“清空 / 0 / 退格”，退格长按清空。最长 32 位，非法字符或超长查询返回空结果，不静默删除数字。

英文大小写使用 ROOT 语言环境归一化。空格、连字符、点、下划线、括号和撇号作为软分隔，允许名称连续输入；其他未知符号形成硬边界，不把两侧文字拼接为完整名称。词组范围见 [拼音依赖](dependencies.md)。

## 混合拼音匹配

每个音节有“首字母编码”和“全音节编码”两条边。用记忆化 DFS 或动态规划，状态为 `(音节位置 i, 查询位置 j)`：

1. 当前边与剩余查询互为前缀时才继续。
2. 查询在当前边中途结束，记为前缀命中。
3. 当前边被完整消费后，转向下一音节。
4. 查询与全部音节同时消费完，记为完整命中。
5. 保留最佳路径及类型，不能让一次先发现的前缀成功覆盖更好的完整命中。

同一起点状态数量为 `O(n × m)`，前缀比较成本需计入真实实现；音节边界子串会尝试其他起点。实现不生成全部混合组合，并保留最佳完整/前缀消费结果。每个应用只保留最好命中，同一 AppId 不重复显示。

低优先级子串从音节边界开始，不任意从音节中间起配。数字编辑距离、漏字和错位容错暂不实现。

## 输入后的匹配等级

等级优先于任何使用习惯加分。建议从高到低：

| 等级 | 类型 |
| --- | --- |
| 1 | 自定义别名完整匹配 |
| 2 | 拼音首字母完整匹配 |
| 3 | 全拼完整匹配 |
| 4 | 英文名称完整匹配 |
| 5 | 首字母前缀匹配 |
| 6 | 全拼前缀匹配 |
| 7 | 混合拼音前缀匹配（含完整消费混合路径） |
| 8 | 英文名称或别名前缀匹配 |
| 9 | 音节边界子串匹配 |

英文名称完整匹配为本次补充的工程建议，避免其被普通前缀压低；混合匹配保持独立低于完整简拼/全拼的等级。后续调整必须更新模型枚举、文档与回归用例。

排序键为：匹配等级升序 → 同级个性化分降序 → 匹配具体程度降序 → 稳定 AppId。置顶和学习不得跨越匹配等级。数字歧义是 T9 的正常性质，不能保证只有一个结果。

## 无输入时的推荐

原会话的初始权重：近期频率 35%、最近使用 25%、时段习惯 15%、工具内启动 15%、长期频率 10%。参数未经过真实数据验证。

- 近期频率采用事件指数衰减 `Σ 2^(-事件年龄/72小时)`，限定近 7 天；长期频率为近 30 天。
- 计数先 `log1p` 饱和处理，再统一到 `[0, 1]`；最近使用可采用 24 小时半衰期指数函数作为初值。
- 时段桶建议为 06–11、11–14、14–18、18–23、23–次日06；数据少于 10 次有效会话时不启用时段信号（阈值为待调优初值）。
- 单项缺失时对可用项权重重新归一化；全部无数据按规范化名称和稳定 ID 排序。
- 置顶是用户主动控制，空查询时优先；查询非空时只在同匹配等级内生效。
- 查询偏好只对当前匹配候选和相同等级加有限分，采用时间衰减，不使一次选择永久固定结果。

## 两条行为数据管道

工具内记录无需使用情况访问权限；建议字段为 AppId、时间、数字查询、结果位置、入口、启动请求结果。当前尚未持久化。系统管道在用户授权后读取近期事件并增量聚合，不能假设系统能补齐过去 30 天逐次启动历史。

系统 Activity resumed 事件不等于一次 App 启动；按资料、包、前后台切换合并会话，应用内部 Activity 切换不得重复计数。同包短时事件去重和会话窗口须用固定样例验证。工具启动与随后系统事件需要关联，整体频率只计一次，工具来源作为额外特征保留；避免简单相加造成双重计数。

维护带回看重叠窗口的聚合水位与幂等键，处理进程重启、重复读取和系统时钟改变。统计时长、会话次数与工具请求次数分别存储。权限撤销后停止系统查询，按照已确认的数据保留策略处理历史数据。

## 稳定性

面板打开时固定使用特征和排序时间；后台数据更新不触发当前会话重排。查询改变才重新计算结果，过时任务丢弃。应用失效可以禁用候选，手指按下后启动目标按已捕获 ID 固定。最后用资料序列号、包名、Activity 名的确定性元组打破平局。
